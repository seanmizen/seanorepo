# REQ-A11Y — Accessibility

Introduced in #152, which added the axe scan and the keyboard suite to CI.

The two requirements below are deliberately separate because the tools cannot
see each other's ground: axe reads the rendered DOM, and cannot tell whether a
control can be reached by Tab or whether focus is visible when it is.

---

## REQ-A11Y-001 — Every route passes WCAG 2.1 AA, in both themes

- **Status:** active
- **Source:** sean
- **Origin:** #152
- **Type:** quality
- **Priority:** P1
- **Statement:** Every declared route shall report zero WCAG 2.1 AA violations
  in both the light and the dark theme.
- **Rationale:** Scanning one theme catches roughly half the defects that
  matter, because contrast is the rule most often broken and dark mode is where
  it breaks — a palette tuned in light mode routinely fails when inverted, and
  nobody notices because nobody re-checks. Running every route in both themes
  makes a new route's contrast regression a CI failure rather than something a
  visitor discovers. A new route is added to `a11y.spec.ts` as part of adding
  it, not afterwards.
- **Verification:** Test — `apps/inside/inside-fe/tests/e2e/a11y.spec.ts` › the `@axe` suite, which runs each route in "WCAG 2.1 AA — light theme" and "WCAG 2.1 AA — dark theme"
- **Relations:** none

## REQ-A11Y-002 — Every control is operable by keyboard, with visible focus

- **Status:** active
- **Source:** sean
- **Origin:** #152
- **Type:** quality
- **Priority:** P1
- **Statement:** Every interactive control shall be reachable by Tab and
  operable without a pointer, with a visible focus indicator.
- **Rationale:** Keyboard operability is a runtime property that a static scan
  cannot observe, so it needs its own suite — REQ-A11Y-001 passing says nothing
  about it. The focus ring is defined once in `app/theme.ts` for everything
  focusable, rather than per component, because a per-component ring is one
  someone will forget on the component that most needs it. Do not restyle focus
  locally to fix a visual complaint; change it in the theme or leave it.
- **Verification:**
  - Test — `apps/inside/inside-fe/tests/e2e/keyboard.spec.ts` › "is reachable and operable with the keyboard alone"
  - Test — `apps/inside/inside-fe/tests/e2e/keyboard.spec.ts` › "the login form can be completed without a mouse"
  - Test — `apps/inside/inside-fe/tests/e2e/keyboard.spec.ts` › "a crumb is reachable by Tab and followed with Enter"
- **Relations:** none
